# План тестирования приложения «Мобильный хоспис»

## 1. Цель тестирования

Проверить работоспособность, устойчивость и удобство основных пользовательских сценариев Android-приложения «Мобильный хоспис», подготовить набор ручных проверок и определить объём последующей автоматизации UI-тестами.

## 2. Объект тестирования

- Android-приложение `V Hospice` (`ru.edu.qamid`).
- Тестовый сервер: `https://students.netoservices.ru/qamid-diplom-backend/`.
- Учётная запись для проверки: `login2` / `password2`.
- Целевая платформа: Android API 36.

## 3. Тестовое окружение

- ОС компьютера: Windows.
- Android Studio и встроенная JDK 21.
- Эмулятор: Pixel 6, Android 16, API 36, x86_64.
- Сетевое подключение к тестовому серверу.
- Сборка приложения: `debug`.

Фактические версии Android Studio, эмулятора и сборки фиксируются перед началом прогона.

## 4. Функциональность в объёме тестирования

### Авторизация

- запуск приложения и отображение формы авторизации;
- вход с корректными данными;
- проверки пустых полей и неверных учётных данных;
- обработка отсутствия сети;
- выход из учётной записи и проверка завершения сессии.

### Главный экран и навигация

- отображение заголовка приложения и блока новостей;
- показ первых трёх новостей;
- сворачивание и разворачивание блока новостей;
- раскрытие карточки новости;
- переход к полному списку новостей;
- переходы через меню `Main` / `News`;
- переход в раздел `Our Mission`;
- переход в меню пользователя.

### Новости

- загрузка и обновление списка;
- раскрытие и сворачивание карточек;
- сортировка по дате в обоих направлениях;
- фильтрация по категории и интервалу дат;
- отмена фильтрации и обработка неполного интервала дат;
- корректное отображение пустого списка и ошибок загрузки.

### Панель управления новостями

- доступ к панели для пользователя с правами администратора;
- отображение статуса `Active` / `Not active`;
- сортировка и фильтрация по категории, датам и статусу;
- создание новости с обязательными полями;
- проверка ограничения даты публикации;
- редактирование новости и изменение активности;
- удаление новости с подтверждением и отменой;
- предупреждение при выходе из формы без сохранения.

### Раздел «Our Mission»

- отображение заголовка и списка тематических цитат;
- разворачивание и сворачивание карточек;
- переходы в `Main`, `News` и выход из учётной записи.


## 5. Виды тестирования

- функциональное тестирование;
- позитивное и негативное тестирование;
- тестирование пользовательского интерфейса и навигации;
- тестирование граничных значений для дат и обязательных полей;
- проверка установки, запуска и повторного запуска;
- проверка поведения при отсутствии сети;
- автоматизированное UI-тестирование критических и стабильных сценариев.

## 6. Подход к тестированию

1. Собрать и установить приложение на эмулятор API 36.
2. Выполнить исследовательский проход по всем доступным экранам.
3. Актуализировать чек-лист и тест-кейсы по фактическому поведению.
4. Выполнить ручной прогон и зафиксировать статус каждой проверки.
5. Оформить дефекты с шагами, ожидаемым и фактическим результатами.
6. Автоматизировать критические сценарии с помощью Espresso.
7. Подключить Allure, добавить названия, описания, шаги и снимки экрана при падении.
8. Выполнить повторный прогон, сформировать отчёт и сравнить время ручной и автоматизированной проверки.

### Планируемый набор автоматизации

Для согласования выбраны 20 тест-кейсов. В `Cases.xlsx` они отмечены «Да» в столбце «Автоматизация»

- Авторизация: `TC-AUTH-001`, `TC-AUTH-002`, `TC-AUTH-005`.
- Навигация: `TC-NAV-001`.
- Сортировка и фильтры новостей: `TC-NEWS-001`, `TC-NEWS-002`, `TC-NEWS-003`, `TC-NEWS-004`.
- Фильтры активности: `TC-CTRL-002`, `TC-CTRL-003`.
- Создание, валидация и выход без сохранения: `TC-CREATE-001`, `TC-CREATE-002`, `TC-CREATE-005`, `TC-CREATE-006`.
- Редактирование и изменение активности: `TC-EDIT-002`, `TC-EDIT-003`.
- Отмена и подтверждение удаления: `TC-DELETE-001`, `TC-DELETE-002`.
- Раздел Our Mission: `TC-MISSION-001`.
- Выход из учётной записи: `TC-LOGOUT-001`.


## 7. Приоритеты

- **Высокий:** вход, выход, загрузка новостей, основная навигация, создание, изменение и удаление новости.
- **Средний:** сортировка, фильтры, статусы, раскрытие карточек, предупреждения об отмене.
- **Низкий:** некритичные визуальные особенности и дополнительные состояния интерфейса.

## 8. Критерии начала тестирования

- проект синхронизируется и собирается без ошибок;
- приложение устанавливается и запускается на API 36;
- тестовый сервер доступен;
- предоставлены рабочие учётные данные;
- исходное состояние тестовых данных позволяет выполнить сценарии.

## 9. Критерии завершения

- выполнены все проверки;
- для каждой проверки указан результат;
- критические дефекты отсутствуют;
- автоматизированные тесты запускаются без ручной подготовки проекта;
- сформирован Allure-отчёт;

## 10. Тестовые данные

- корректный пользователь: `login2` / `password2`;
- неверные данные: `wrongLogin` / `wrongPassword`;
- тестовые новости создаются с уникальным заголовком, содержащим дату и время запуска;
- после проверки созданные тестовые новости удаляются;
- категории выбираются из списка, который возвращает приложение.

## 11. Инструменты

- Android Studio и Android Emulator;
- JUnit 4;
- Espresso и Espresso Intents;
- UI Automator — только для системных элементов при необходимости;
- Allure для формирования отчёта;
- Git для хранения проекта и результатов работы.
